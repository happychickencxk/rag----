# 小程序需求与实现缺口

> 最近核对：2026-06-27。结论来自 `docs` 下 5 份 Word 文档和当前 `frontend/wechat_miniprogram/miniprogram` 源码，不以旧路线图代替原始需求。

## 范围结论

本仓库只负责微信小程序前端。小程序的核心验收链路是：

1. 获取微信登录态并换取 JWT。
2. 获取用户有权访问的知识库并完成切换。
3. 创建或恢复会话，发送问题并展示回答。
4. 支持多轮追问和流式输出。
5. 展示可核验、受权限控制的引用来源。
6. 查看、搜索、恢复和删除历史会话。
7. 对回答进行点赞、点踩、无引用或纠错反馈。
8. 在模型、知识库、权限和网络异常时展示可操作的状态。

用户、部门、角色、文档解析、索引重建、质量工单、统计看板、模型配置和审计日志属于后端或 Web 管理后台，不应迁入小程序。

## 页面需求对照

| 页面或入口 | 核心要求 | 当前状态 | 主要缺口 |
| --- | --- | --- | --- |
| 登录与启动鉴权 | `wx.login()`、微信 code 登录、Token 保存和刷新、失效后重新登录 | 缺失 | 没有登录页、路由守卫、Token 持久化和刷新队列 |
| 问答页 | 知识库切换、提问、多轮追问、流式输出、复制、反馈、异常提示 | 仅静态原型 | 使用固定回答；发送后覆盖全部消息；没有会话 ID、消息 ID、加载态、取消和真实重试 |
| 知识库页与切换弹层 | 获取有权限知识库、搜索、分页、空态、切换当前知识库 | 仅静态原型 | 使用 `utils/mock.js`；搜索只过滤本地数组；没有加载、失败和分页 |
| 历史会话页 | 分组、搜索、恢复消息、删除会话 | 仅静态原型 | 点击只写入 `lastQuestion`，问答页没有读取；长按删除仅提示占位 |
| 引用详情页 | 文档名、章节、原文、命中高亮、相似度、Rerank、更新时间、权限保护 | 仅静态原型 | 使用固定引用；接口字段不足；受限引用仍可能渲染完整 `excerpt`，必须优先修复 |
| 提交反馈页 | 携带真实问题、回答和消息 ID，提交反馈类型及说明 | 仅静态原型 | 摘要固定；`type=citation` 未处理；提交后只切换本地成功页 |
| 我的页 | 当前用户资料、退出登录 | 仅静态原型 | 用户资料、统计数字、知识库权限均为固定值；退出登录未实现 |
| 异常状态 | 无依据、低置信、无权限、超时、敏感拦截、空历史、空知识库 | 只有预览页 | 状态没有接入任何真实页面或请求流程 |
| 文件中心 | 用户明确要求的上传入口和下载页 | 交互占位 | 只选择本地文件；未上传、未下载、未选择知识库；支持格式与接口文档冲突 |
| 知识库详情或文档浏览 | 查看知识库详情及可访问文档 | 缺失 | 是否纳入小程序首版需确认；接口文档称小程序支持“文档浏览” |

## 当前代码中的明确占位

- `app.js` 只有内存中的空 Token 字段，仍初始化云开发模板，没有认证恢复。
- `utils/mock.js` 提供所有知识库、回答、引用、会话、用户和状态数据。
- `pages/chat/index.js` 的 `sendQuestion` 总是返回同一个答案，并将消息数组替换为一问一答，不是多轮会话。
- `pages/chat/index.js` 的点赞、点踩只修改本地 `feedbackValue`；重新生成和语音输入只显示提示。
- `pages/history/index.js` 的 `openSession` 没有获取消息，`deleteSession` 没有调用删除接口。
- `pages/citation/detail.js`、`pages/feedback/submit.js` 和 `pages/profile/index.js` 都没有真实接口。
- `pages/files/index.js` 只调用 `wx.chooseMessageFile`；“下载”按钮没有下载行为。
- 我的页“消息通知”和“关于系统”没有点击行为；“异常状态预览”是开发验收入口，不是正式业务入口。
- `pages/index`、`pages/example`、`components/cloudTipModal` 和相关云开发代码是未注册的 QuickStart 遗留。

## P0：核心链路与安全

### 1. 请求与认证基础

实现内容：

- 可配置 API 地址，不把密钥或生产地址写死在源码。
- 统一封装 `wx.request`，自动附加 `Authorization`、`X-Client-Type: wechat` 和请求 ID。
- 使用微信本地存储保存 access token、refresh token 和过期时间。
- 401 时只允许一个刷新请求，其它请求等待刷新结果；刷新失败后清理登录态。
- 映射 400、401、403、404、413、429、500、503 和网络超时。

验收标准：

- 页面代码不直接拼接 Token 和重复处理通用错误。
- 并发 401 不会发起多次刷新。
- API 基础地址不会出现重复 `/api/v1/api/v1`。

### 2. 微信登录与当前用户

接口：

- `POST /api/v1/auth/wechat-login`
- `POST /api/v1/auth/refresh`
- `GET /api/v1/auth/profile`
- `POST /api/v1/auth/logout`

验收标准：

- 无有效 Token 时进入登录或授权流程。
- 登录成功后恢复原目标页面。
- 我的页使用真实用户信息，退出后清理本地状态。

### 3. 非流式问答和会话

接口：

- `POST /api/v1/qa/sessions`
- `POST /api/v1/qa/query`，先使用 `stream=false`
- `GET /api/v1/qa/sessions/{sessionId}/messages`

验收标准：

- 新问题追加到当前消息数组，不覆盖历史消息。
- 发送期间防止重复提交，失败后可保留问题并重试。
- 保存 `session_id`、`message_id` 和引用列表。
- 切换知识库时明确创建新会话或确认清空当前上下文。

### 4. 引用权限保护

验收标准：

- 403 或受限引用不得渲染完整原文。
- 列表和详情页只能展示后端明确允许的摘要字段。
- 不用前端本地 `permitted` 字段模拟安全边界。

## P1：完整问答闭环

### 1. 知识库

- 对接 `GET /api/v1/knowledge-bases` 和 `GET /api/v1/knowledge-bases/{kbId}`。
- 支持加载、分页、搜索无结果、无可访问知识库和 403 状态。
- 建立后端字段到页面字段的适配层，不让页面直接依赖 snake_case。

### 2. 流式问答

- 以 API-Q02 定义的 POST SSE 为当前主方案。
- 使用微信小程序支持的分块响应能力解析 `data:` 事件，处理拆包、粘包和 UTF-8 边界。
- `done=false` 追加文本；`done=true` 保存消息 ID 和引用。
- 支持超时、中断、重试和页面卸载时终止请求。

### 3. 历史会话

- 对接会话列表、消息列表和单会话删除接口。
- 点击历史记录必须恢复真实消息和当前知识库。
- 搜索策略需确认使用本地已加载数据还是新增服务端 `keyword` 参数。

### 4. 引用与反馈

- 引用详情使用真实 session ID、message ID 和 chunk ID。
- 反馈页面必须携带真实问题、回答摘要和消息 ID。
- 点赞、点踩、无引用和详细纠错原因需要统一映射并防止重复提交。

### 5. 页面状态

- 把 `states` 中的状态组件化并接入真实页面。
- 每个列表页至少支持加载、空数据、错误和重试。
- 问答页区分检索中、生成中、无依据、低置信、无权限、超时和敏感拦截。

## P2：扩展能力

- 语音输入目前只要求“预留”，不是首版阻塞项。
- 会话导出和分享在需求中属于可弱化能力。
- 消息通知、关于系统、个人统计和常用知识库需要产品说明或新接口。
- 知识库详情与文档浏览是否进入小程序首版需要确认。
- 文件中心需要先确认使用角色、上传元数据流程和下载接口，再接真实能力。
- 清理未注册的云开发 QuickStart 页面、组件、云函数和初始化代码。

## 接口冲突与待确认

1. API 文档同时给出“基础 URL 含 `/api/v1`”和“接口路径也含 `/api/v1`”。请求层必须只保留一次前缀。
2. 概要设计提到 WebSocket，API-Q02 明确规定 POST SSE。小程序首版建议以 API-Q02 为准。
3. 消息反馈接口只接受 `like`、`dislike`、`no_citation`，但反馈对象枚举又包含 `correction`。当前六种细分原因没有明确字段。
4. 普通用户的知识库列表按文档只返回有权限项，但当前 UI 还展示“无访问权限”知识库。若保留该行，后端需要返回可见但不可访问的记录和权限字段。
5. 引用接口没有返回知识库名称、更新时间、授权状态和命中高亮，无法完整驱动现有引用详情页。
6. 文档上传接口只支持 `pdf/docx/md/txt/html/csv`，当前文件页却写有 Excel、PPT，并包含 `.xlsx` 示例。
7. 文档接口没有安全下载接口；`storage_path` 不能直接作为客户端下载地址。
8. 清空全部历史没有批量接口，当前只有逐个删除会话。
9. 我的页统计数字和消息通知没有对应的小程序接口。
10. API 文档中所有主要接口的“完成情况”均为“待开发”，前端接入前需要确认后端实际可用地址和已完成接口。

## 建议首个实现批次

首批只完成以下内容，不同时铺开所有页面：

1. 配置、请求客户端、Token 存储和统一错误。
2. 微信登录、刷新 Token、当前用户和退出登录。
3. 知识库列表真实接口与 mock/real 数据源切换。
4. 非流式问答、会话创建和消息追加。
5. 修复受限引用原文泄露，并把异常状态接入问答页。
