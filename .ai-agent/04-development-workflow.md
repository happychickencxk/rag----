# 开发协作流程

## 开始任务前

1. 先读 `.ai-agent/README.md`。
2. 根据任务类型读取相关文档。
3. 用 `git status -sb` 确认工作区状态。
4. 读取当前代码，不凭记忆改文件。

## 文档与注释规范

- README、AI agent 文档、提交说明、重要代码注释使用汉语。
- 注释只解释非显而易见的业务规则、接口约定或复杂状态，不写空泛注释。
- 接口字段、状态码、枚举值必须和接口文档或后端实际实现保持一致。
- 如果接口文档与代码产生差异，应在 `.ai-agent/03-api-contract.md` 标注当前取舍。

## 实现流程

1. 先确定本次功能范围。
2. 修改代码或文档。
3. 同步更新 `.ai-agent` 中对应说明。
4. 运行与改动相匹配的检查。
5. 使用一个清晰中文 commit 提交。
6. 推送到 `origin/main`。

当前仓库初期采用直接推送 `main` 的方式。若后续多人协作或改动风险增大，再切换为分支加 PR。

## 检查要求

纯文档改动：

```powershell
git status -sb
git diff --check
```

前端代码改动：

```powershell
cd frontend
npm install
npm run build
```

如果依赖安装失败，先记录错误原因，不要静默跳过。

## Commit 规则

- 一个明确功能点一个 commit。
- commit 信息使用简短中文动宾结构。
- 示例：
  - `完善项目说明与AI协作文档`
  - `拆分问答页组件`
  - `接入知识库列表接口`
  - `完善引用详情异常状态`

## 推送验证

提交后：

```powershell
git log -1 --stat
git push origin main
git ls-remote --heads origin main
```

推送失败时先判断是认证问题、网络问题还是远程分支变化。不要用强制推送覆盖远程，除非用户明确要求。

## 不要做的事

- 不要把 AI agent 文档散落到主目录。
- 不要删除或覆盖用户未确认的改动。
- 不要把密钥、token、`.env` 提交到仓库。
- 不要在小程序端加入后台管理页面。
- 不要在没有检查接口契约的情况下随意发明字段。
