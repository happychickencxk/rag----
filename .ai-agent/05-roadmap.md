# 前端推进路线

## P0：仓库与文档基线

目标：让项目可被人类和 AI agent 稳定接手。

- 补齐根 README。
- 建立 `.ai-agent` 文档体系。
- 明确小程序端边界和接口契约。
- 配置 `.gitignore`。
- 提交并推送到 private GitHub 仓库。

## P1：前端结构整理

目标：降低 `App.tsx` 单文件复杂度，保持行为不变。

- 拆出公共类型和模拟数据。
- 拆出布局组件：NavBar、TabBar、BottomSheet。
- 拆出问答、知识库、历史、引用、反馈、我的页模块。
- 保留当前视觉和交互，不做大范围重设计。
- 拆分后运行构建检查。

## P2：接口接入准备

目标：让模拟数据可以逐步切换到真实后端。

- 新增统一请求封装，自动带 `Authorization` 和 `X-Client-Type: wechat`。
- 新增 token 存取和刷新逻辑。
- 建立接口类型定义，与 `03-api-contract.md` 对齐。
- 实现统一错误映射：401、403、404、429、500、503。
- 先接入知识库列表和用户信息，再接入问答。

## P3：问答主链路接入

目标：完成小程序最关键的真实问答体验。

- 创建或恢复会话。
- 发送问题到 `POST /api/v1/qa/query`。
- 支持非流式响应作为基础能力。
- 支持 `stream=true` 的 SSE 流式输出。
- 渲染引用来源和最终 `message_id`。
- 处理无依据、低置信度、无权限、模型超时、敏感词拦截。

## P4：引用、历史和反馈闭环

目标：补齐可信回答和质量反馈能力。

- 引用详情接入 `citations` 接口。
- 历史会话接入会话列表与消息列表。
- 删除历史会话调用软删除接口。
- 点赞、点踩、纠错提交到反馈接口。
- 反馈成功后给出明确状态。

## P5：真实小程序迁移准备

目标：为 WXML/WXSS 或 uni-app 迁移降低成本。

- 保持页面为单列移动端结构。
- 将 Web 专用能力与业务状态解耦。
- 整理设计 token，映射到 rpx。
- 输出页面、组件、接口字段清单。
- 保留 React 原型作为交互验收版本。
